VTR — VJs' Timeline Recorder: record, edit, and replay OSC for VJ performances.

# Commit messages & PR titles

Always use conventional commits: `type(scope)?: subject`.
Types: feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert.
Scopes in use: `tap` (vtr-tap), `player` (vtr-player), `editor` (vtr-editor), `td` (TouchDesigner component).

# Commands

```sh
./run [project.oscproj]     # launch editor in dev mode; builds the rust workspace only if binaries are MISSING
                            # after Rust changes, rebuild manually: cargo build --release

# Rust — one cargo workspace at the repo root: vtr-tap + vtr-player
cargo test                          # unit + e2e + conformance, both crates
cargo test -p vtr-player            # one crate
cargo test --release -- --ignored   # 120Hz soak test

# Editor (Electron)
cd vtr-editor
npm run dev                         # optionally: -- path/to/project.oscproj
npm run lint / typecheck / test:unit
npx vitest run src/main/merge.test.ts        # single unit test file
npm run test:e2e                    # playwright; needs vtr-tap debug build
npx playwright test e2e/app.spec.ts          # single e2e spec
RUN_LAUNCHD=1 npx playwright test e2e/launchd.spec.ts   # launchd agent test (opt-in)
```

# Architecture

Data flow (see `docs/ARCHITECTURE.md` for full diagrams + port table):

```
TouchOSC → vtr-tap → clips/*.jsonl → vtr-editor → session.jsonl → vtr-player → TouchDesigner
 (control)  (record)                  (arrange)                    (replay)      (visuals)
```

- **vtr-tap** (Rust): UDP proxy :10010 → :10011. Forwards app OSC unchanged, logs parsed copies as JSONL. `/vtr/*` messages are control: never forwarded to the app, never recorded, relayed to vtr-player (:10013). `/vtr/clock` beacons stamp events with TD-timeline time (`tl`). Every new source IP is announced to the player as `/vtr/origin` so it knows who to feed back. Editor controls the tap over a unix-socket JSON Lines API (`vtr-tap.sock`).
- **vtr-player** (Rust, `vtr-player/`): resolver server. Replays `session.jsonl`, answers per-frame `resolve` queries over a unix socket (TD blocks each cook on the response). Its **push transport is the single authoritative playhead**: editor, TD (realtime on), and controllers all read/write it; writes carry `origin` + generation counter `gen` for echo suppression. It also follows the tap's rec event log: a take start primes the transport to `tl` and plays, so sync clients land on the punch-in point. Feeds controllers back on the echo port: rec state plus the playback values (coalesced, off while recording). Targets are the senders it hears about plus the pinned `--echo-host`.
- **vtr-editor** (Electron): DAW-style editor. Spawns and monitors both tap and player; delegates preview playback to the player (inline load with routes + transport writes), so the player's resolver is the only OSC emitter. `src/main` (node side, one module per concern with colocated `.test.ts`), `src/renderer` (React UI), `src/shared` (types + edit ops).
- **td/**: `vtr.tox` (source `src/vtr_ext.py`, generated by `build/build_vtr.py` — see `td/README.md`). Modeless: every frame it beacons `/vtr/clock` and blocks on one resolve; `project.realTime` picks the position source (on = bidirectional transport sync, off = TD timeline − `Offset` for deterministic renders).

Playback-resolution semantics are defined by `vtr-player/tests/conformance_*.rs`.

Key references in README.md: the `/vtr` OSC control protocol table (v2), JSONL event schema, `.oscproj` bundle format. Design specs live in `docs/tasks/<topic>/`.

The editor writes nothing to its cwd: recordings, control socket, and undo log go to userData (`~/Library/Application Support/VTR/`) or the open project bundle.
