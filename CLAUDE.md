# Commit messages & PR titles

Always use conventional commits: `type(scope)?: subject`.

# Commands

```sh
./run [project.oscproj]     # launch editor in dev mode; builds tap workspace only if binaries are MISSING
                            # after Rust changes, rebuild manually: cd osc-tap && cargo build --release

# Rust — one cargo workspace: osc-tap + vtr-player
cd osc-tap
cargo test                          # unit + e2e + conformance, both crates
cargo test -p vtr-player            # one crate
cargo test --release -- --ignored   # 120Hz soak test

# Editor (Electron)
cd osc-editor
npm run dev                         # optionally: -- path/to/project.oscproj
npm run lint / typecheck / test:unit
npx vitest run src/main/merge.test.ts        # single unit test file

npx playwright test e2e/app.spec.ts          # single e2e spec
RUN_LAUNCHD=1 npx playwright test e2e/launchd.spec.ts   # launchd agent test (opt-in)

# Python resolver reference
cd td && uv run pytest
```

# Architecture

Data flow (see `docs/ARCHITECTURE.md` for full diagrams + port table):

```
TouchOSC → osc-tap → clips/*.jsonl → osc-editor → session.jsonl → vtr-player → TouchDesigner
 (control)  (record)                  (arrange)                    (replay)      (visuals)
```

- **osc-tap** (Rust): UDP proxy :10010 → :10011. Forwards app OSC unchanged, logs parsed copies as JSONL. `/vtr/*` messages are control: never forwarded to the app, never recorded, relayed to vtr-player (:10013). `/vtr/clock` beacons stamp events with TD-timeline time (`tl`). `--td-notify` (:10014) reports rec state changes to the tox. Editor controls the tap over a unix-socket JSON Lines API (`osc-tap.sock`).
- **vtr-player** (Rust, `osc-tap/vtr-player/`): resolver server. Replays `session.jsonl`, answers per-frame `resolve` queries over a unix socket (TD blocks each cook on the response). Its **push transport is the single authoritative playhead**: editor, TD (`sync` mode), and controllers all read/write it; writes carry `origin` + generation counter `gen` for echo suppression.
- **osc-editor** (Electron): DAW-style editor. Spawns and monitors both tap and player; mirrors its preview into the player so sync clients follow. `src/main` (node side, one module per concern with colocated `.test.ts`), `src/renderer` (React UI), `src/shared` (types + edit ops).
- **td/**: `vtr.tox` (source `src/vtr_ext.py`, generated by `build/build_vtr.py` — see `td/README.md`) and `vtr_core`, a pure-Python reference resolver. The tox does NOT use vtr_core.

Conformance chain: `td/tests/` (pytest) defines playback-resolution semantics; those tests are ported 1:1 to `osc-tap/vtr-player/tests/`. Resolver semantic changes must update both.

Key references in README.md: the `/vtr` OSC control protocol table (v2), JSONL event schema, `.oscproj` bundle format. Design specs live in `docs/tasks/<topic>/`.

The editor writes nothing to its cwd: recordings, control socket, and undo log go to userData (`~/Library/Application Support/VTR/`) or the open project bundle.
